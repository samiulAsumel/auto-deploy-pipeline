Deployment Flow

9 Steps. One Command.

Every deploy follows the same battle-tested sequence. Each step is modular — you can skip tests, add migrations, or extend any step without touching the orchestrator.

STEP 01
🔍
Pre-Flight Checks
Disk space, git access, database reachability, required tools. Abort before any code is touched.
STEP 02
💾
Backup Current
Records the current release path. The releases/ directory retains all versions — no file copy needed.
STEP 03
📦
Pull Code
git clone --depth 1 into a timestamped release dir. Links shared .env/uploads. Installs deps and builds.
STEP 04
🧪
Run Tests
Runs your test suite inside the new release. Abort fires before any switch — production is never touched on failure.
STEP 05
⚡
Switch Version
Atomic ln -sfn swaps the /var/www/current symlink. A single syscall — zero downtime during the switch.
STEP 06
🔄
Restart Services
pm2 reload / gunicorn restart / php-fpm reload. nginx config test then reload. Falls back gracefully.
STEP 07
❤️
Verify Deployment
Polls HEALTH_URL up to 3 times. HTTP 200 = pass. Failure triggers immediate auto-rollback.
STEP 08
🧹
Cleanup Releases
Keeps the last KEEP_RELEASES directories (default 5). Older releases are automatically removed.
STEP 09
📣
Notify
Slack green/red message and/or email with deploy ID, environment, commit hash, user, and duration.

⚡

          
Auto-Trigger Conditions

          

            Health check returns non-200 after all retries, or any uncaught error after the symlink switch.
          

          AUTO_ROLLBACK=true  # in config.conf
HEALTH_RETRIES=3    # attempts before abort
HEALTH_WARMUP=10    # seconds before first check
        


        

          
↩

          
Manual Rollback

          

            Run from any terminal. Restores previous release, restarts services, and verifies in one command.
          

          ./deploy.sh production --rollback
# or after install:
deploy production --rollback
        


        

          
🔔

          
Instant Notification

          

            Yellow Slack warning with release IDs, environment, timestamp, and reason. Email log attached.
          

          SLACK_WEBHOOK="https://hooks.slack.com/..."
NOTIFY_EMAIL="devops@company.com"
NOTIFY_METHOD="both"
        


      


    

    


    


    
    

      
Features

      
Everything Built In

      
No external tools. No Docker. No CI/CD platform required. Pure Bash that runs anywhere.


      

        

          
⚡

          
Zero-Downtime Deploy

          
Atomic symlink switch is a single syscall. Traffic never hits an incomplete release.

        

        

          
🔁

          
Auto-Rollback

          
Health check fails → previous release restored automatically. No human intervention needed.

        

        

          
🧪

          
Pre-Deploy Tests

          
Test suite runs before any production change. Failed tests abort the deploy entirely.

        

        

          
📣

          
Slack + Email Alerts

          
Colour-coded Slack messages (green/red/yellow) with commit, env, user, and duration.

        

        

          
🌍

          
Multi-Environment

          
production / staging / dev configs. One command, one flag: ./deploy.sh staging.

        

        

          
🗂️

          
Shared Files

          
.env, uploads, and storage symlinked from a shared dir — persisted across every deploy.

        

        

          
🗑️

          
Release Cleanup

          
Keeps KEEP_RELEASES old versions (default 5). Older release dirs are automatically pruned.

        

        

          
🔒

          
Lock File

          
Prevents concurrent deploys with a PID-based lock. Stale locks from dead processes are auto-cleared.

        

        

          
🌐

          
App-Type Aware

          
npm ci / pip install / composer install / static — install logic adapts to your APP_TYPE.
